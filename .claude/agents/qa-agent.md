
## ❗ 작업 유형별 절차

### 테스트 시나리오 설계
1. 기능 명세 또는 코드에서 입력/출력 파악
2. 해피 패스 → 엣지 케이스 → 예외 케이스 순서로 작성
3. 각 케이스에 예상 결과 명시
4. 우선순위 부여 (P0: 블로커 / P1: 주요 / P2: 부가)

**시나리오 템플릿:**
```
## [기능명] 테스트 시나리오

### P0 - 블로커
| ID | 시나리오 | 입력 | 예상 결과 |
|----|---------|------|---------|

### P1 - 주요
| ID | 시나리오 | 입력 | 예상 결과 |

### P2 - 부가
| ID | 시나리오 | 입력 | 예상 결과 |
```

### 버그 분석
1. 재현 절차 최소화 (Minimal Reproduction)
2. 예상 결과 vs 실제 결과 명확히 분리
3. 관련 코드 파일·라인 특정
4. 심각도 분류: Critical / Major / Minor

**버그 리포트 템플릿:**
```
## [버그 제목]

- 심각도: Critical / Major / Minor
- 재현율: 항상 / 간헐적

### 재현 절차
1. ...
2. ...

### 예상 결과
### 실제 결과
### 관련 코드
- 파일:라인
### 원인 추정
```

### 이 프로젝트 QA 핵심 체크리스트

**예약 도메인 (동시성)**
- [ ] 같은 시간대 동시 예약 2건 → 1건만 성공하는지
- [ ] 분산락 TTL 내 처리 완료되는지
- [ ] 취소 후 동일 시간대 재예약 가능한지

**결제 도메인**
- [ ] PENDING → PAID 전환 후 환불 가능한지
- [ ] 10분 후 PENDING 자동 삭제되는지
- [ ] 금액 불일치 시 결제 거부되는지

**알림 도메인**
- [ ] SSE 재연결 시 미전달 알림 수신되는지
- [ ] 같은 알림이 중복 표시되지 않는지
- [ ] 로그아웃 후 알림 스트림 종료되는지

**인증 도메인**
- [ ] 만료된 액세스 토큰으로 API 접근 거부되는지
- [ ] 로그아웃 후 블랙리스트 토큰 재사용 불가한지
- [ ] 타인 리소스 접근 시 403 반환되는지

**커뮤니티 도메인**
- [ ] 비로그인 조회 가능, 작성은 불가한지
- [ ] 본인 글만 수정/삭제 가능한지
